# 项目全流程总结：从想法到能跑的产品

> 写于 2026-08-16 ｜ 阶段 0~3 完工后 ｜ 阅读方式：不赶时间，一段一段看

## 1. 一句话：这项目是什么

用户答 10 道情境题 → AI（DeepSeek）读答案 → 生成一份专属 MBTI 人格报告。

它小，但它是一个**完整的 AI 产品**：有画面、有大脑、有掌柜、有钥匙。

## 2. 全程地图（最核心的一张图）

```
你（浏览器）
 │  打开 http://localhost:5173
 ▼
【前端 frontend/】答题页 ← Vue 画的画面
 │  点"生成我的报告"，答案打包飞出去
 ▼
【后端 server/】/api/analyze ← Express 写的掌柜
 │  ① 拿出 prompt.md 工作手册
 │  ② 带上 .env 里的 API key
 ▼
【DeepSeek API】AI 大脑（别人造好的，按次收费）
 │  5~10 秒后返回报告 JSON
 ▼
后端原样转发 → 前端报告页渲染 → 你看到报告
```

三个角色的分工：

| 角色 | 住哪 | 干什么 | 不能干什么 |
|---|---|---|---|
| 前端 | 你的电脑（5173 窗口） | 画面：收答案、展报告 | 藏 key（浏览器代码人人可看） |
| 后端 | 你的电脑（3001 窗口） | 掌柜：拼指令、带 key 调 AI | 画画面 |
| DeepSeek | 云上 | 读答案、写报告 | —— |

浏览器有规矩：**5173 的网页不许直接敲 3001 的门**（跨域禁令）。所以 vite.config.js 里设了个中转站（代理），前端以为自己一直跟 5173 说话。

开发时三个角色都在你电脑上；上线（阶段 4）后前端后端搬到 Vercel 上，DeepSeek 还在云上，你电脑关机也不影响别人访问。

## 3. 走过的四段路

### 阶段 0：想清楚（docs/product-spec.md）

**做了什么**：定玩法（MBTI 八维）、写 10 道原创题、定报告结构、定两条红线（不引原话、不露推断逻辑）。

**为什么先做这个**：写代码前先把"要做什么"写死。后面所有阶段都在执行这份说明书——产品思维第一步：想清楚再动手。

**你学到了**：产品说明书就是项目的宪法。

### 阶段 1：教会 AI 干活（docs/prompt.md）

**做了什么**：写了一份给 AI 的"工作手册"——角色、输入格式、毕比模型分析框架、权重表、输出 JSON 格式、六条质量红线、固定免责文案。并用你真实填写的 10 题答案（test-input.json）实测验收：判型全对、红线全守。

**为什么重要**：**这是 AI 应用开发最核心的技能**。AI 是雇来的专家，prompt 就是劳动合同——写得越清楚，活干得越好。

**你学到了**：AI 应用开发 ≠ 写代码，写指令才是灵魂。测试先行的习惯。

### 阶段 2：做出画面（frontend/）

**做了什么**：用 Vue3 + Vite 搭出答题页（10 道题 + 选项 + 理由框）和报告页，先用假数据把画面跑通。

**为什么用假数据**：画面和 AI 是两件独立的事，一件一件做。画面跑通之前，接了 AI 也看不出画面有没有问题。

**你学到了**：前端管画面，数据可以后接——"先让房子能住人，再接通水电"。

### 阶段 3：接通大脑（server/）

**做了什么**：
1. 搭后端骨架（Express，3001 窗口）
2. 写 `/api/analyze`：收答案 → 拼 prompt.md → 调 DeepSeek → 返回报告
3. key 放进 `.env`（绝不进 git），配 `.env.example` 模板
4. 前后端连通：Vite 代理绕开跨域禁令，答题页提交改调真接口
5. 坏天气装修：AI 分析中的等待提示、失败页（重试/返回修改）、后端把错误翻译成人话

**你学到了**：前后端分离、环境变量安全、跨域与代理、错误处理的产品思维、以及 Windows 杀不死的孤儿进程（netstat + taskkill）。

## 5. 点下按钮后的 10 秒（数据的一次旅行）

1. 你点"生成我的报告"→ 前端先检查 10 题都选了
2. 前端把答案整理成 prompt.md 规定的格式（含选项全文和理由）
3. 画面切到"🤔 AI 正在阅读你的答案…"
4. `fetch('/api/analyze')` 发出请求 → 到 5173 → 被代理转交 3001
5. 后端收到：检查格式 → 检查 key 在不在
6. 后端把 prompt.md 全文 + 你的答案打包，POST 给 DeepSeek
7. DeepSeek 读 5~10 秒，写出一份 JSON 报告（判型 + 八维 + 建议 + 免责声明）
8. 后端转发 → 前端切到报告页渲染 → 你看到"INTP · 逻辑学家"
9. 任何一环断了 → 失败页：人话错误 + 重试 + 返回修改（答案保留）

## 7. 接下来：阶段 4

- **差异化改造（2026-08-16 定）**：产品卖点从"测八维"改押"AI 读理由"——
  1. 两道核心推断题理由必填；理由框 placeholder 用诱导式文案
  2. 定位文案改口："让 AI 看穿你"（卖点 = 自由文本解读，不是测 MBTI）
  3. 报告呼应理由细节（引用开关仍默认关）
  4. 上线后盯死一个指标：**理由填写率**（= 产品命根子）

- **部署上线**：frontend + server 搬到 Vercel（免费），key 存 Vercel 环境变量，拿公网网址

## 8. 差异化：这个产品凭什么存在（2026-08-16 深夜反思）

一个必须诚实回答的问题：如果只是"选项 → 判型"，规则引擎在前端就能干，AI 纯属多此一举。AI 真正承重的只有两处：

1. **读理由**：自由文本解读——同一选项、不同动机，是规则引擎读不懂的人话（实测：Q6 选 B 但理由暴露 Si 动机，AI 判对了）
2. **写报告**：从"这个人的答案"里长出具体描述，而不是千人一面的模板

结论：**差异化 = AI 读理由 + 个性化报告**。理由框是主角，选项是快车道。理由没人填 → 差异化塌陷，所以理由填写率是命根子指标。
