# 项目全流程总结：从想法到能跑的产品

> 写于 2026-08-16 ｜ 2026-08-17 阶段 4 完工后更新 ｜ 阅读方式：不赶时间，一段一段看

## 1. 一句话：这项目是什么

用户答 20 道情境题 → AI（DeepSeek）读答案 → 生成一份专属 MBTI 人格报告。

它小，但它是一个**完整的 AI 产品**：有画面、有大脑、有掌柜、有钥匙。

## 2. 全程地图（最核心的一张图）

```
你（浏览器）
 │  打开 http://localhost:5173
 ▼
【前端 frontend/】答题页 ← Vue 画的画面
 │  点"生成我的报告"，答案打包飞出去
 ▼

 │  ① 拿出 prompt.md 工作手册
 │  ② 带上 .env 里的 API key
 ▼
【DeepSeek API】AI 大脑（别人造好的，按次收费）
 │  5~10 秒后返回报告 JSON
 ▼
后端原样转发 → 前端报告页渲染 → 你看到报告
```

三个角色的分工：

| 角色 | 住哪 | 干什么 | 不能干什么 |
|---|---|---|---|
| 前端 | 你的电脑（5173 窗口） | 画面：收答案、展报告 | 藏 key（浏览器代码人人可看） |
| 后端 | 你的电脑（3001 窗口） | 掌柜：拼指令、带 key 调 AI | 画画面 |
| DeepSeek | 云上 | 读答案、写报告 | —— |

浏览器有规矩：**5173 的网页不许直接敲 3001 的门**（跨域禁令）。所以 vite.config.js 里设了个中转站（代理），前端以为自己一直跟 5173 说话。

## 3. 走过的四段路

### 阶段 0：想清楚（docs/product-spec.md）

**做了什么**：定玩法（MBTI 八维）、写 10 道原创题、定报告结构、定两条红线（不引原话、不露推断逻辑）。

**为什么先做这个**：写代码前先把"要做什么"写死。后面所有阶段都在执行这份说明书——产品思维第一步：想清楚再动手。

**你学到了**：产品说明书就是项目的宪法。

### 阶段 1：教会 AI 干活（docs/prompt.md）

**做了什么**：写了一份给 AI 的"工作手册"——角色、输入格式、毕比模型分析框架、权重表、输出 JSON 格式、六条质量红线、固定免责文案。并用你真实填写的 10 题答案（test-input.json）实测验收：判型全对、红线全守。

**为什么重要**：**这是 AI 应用开发最核心的技能**。AI 是雇来的专家，prompt 就是劳动合同——写得越清楚，活干得越好。

**你学到了**：AI 应用开发 ≠ 写代码，写指令才是灵魂。测试先行的习惯。

### 阶段 2：做出画面（frontend/）

**做了什么**：用 Vue3 + Vite 搭出答题页（10 道题 + 选项 + 理由框）和报告页，先用假数据把画面跑通。

**为什么用假数据**：画面和 AI 是两件独立的事，一件一件做。画面跑通之前，接了 AI 也看不出画面有没有问题。

**你学到了**：前端管画面，数据可以后接——"先让房子能住人，再接通水电"。

### 阶段 3：接通大脑（server/）

**做了什么**：
1. 搭后端骨架（Express，3001 窗口）
2. 写 `/api/analyze`：收答案 → 拼 prompt.md → 调 DeepSeek → 返回报告
3. key 放进 `.env`（绝不进 git），配 `.env.example` 模板
4. 前后端连通：Vite 代理绕开跨域禁令，答题页提交改调真接口
5. 坏天气装修：AI 分析中的等待提示、失败页（重试/返回修改）、后端把错误翻译成人话

**你学到了**：前后端分离、环境变量安全、跨域与代理、错误处理的产品思维、以及 Windows 杀不死的孤儿进程（netstat + taskkill）。

## 5. 点下按钮后的 10 秒（数据的一次旅行）

1. 你点"生成我的报告"→ 前端先检查 20 题都选了（核心题还要理由）
2. 前端把答案整理成 prompt.md 规定的格式（含选项全文和理由）
3. 画面切到"🤔 AI 正在阅读你的答案…"
4. `fetch('/api/analyze')` 发出请求 → 到 5173 → 被代理转交 3001
5. 后端收到：检查格式 → 检查 key 在不在
6. 后端把 prompt.md 全文 + 你的 20 题答案打包，POST 给 DeepSeek
7. DeepSeek 读 10~20 秒，写出一份 JSON 报告（判型 + 八维 + 评分 + 压力篇 + 配对 + 免责声明）
8. 后端"验货"：按格式合同逐项检查（字段齐不齐、评分在不在、数组长度对不对）——不合格就把"差评"发回去让 AI 重写，最多 3 次
9. 验货通过 → 前端切到报告页渲染 → 你看到报告
10. 任何一环断了 → 失败页：人话错误 + 重试 + 返回修改（答案保留）

## 8. 差异化：这个产品凭什么存在（2026-08-16 深夜反思）

一个必须诚实回答的问题：如果只是"选项 → 判型"，规则引擎在前端就能干，AI 纯属多此一举。AI 真正承重的只有两处：

1. **读理由**：自由文本解读——同一选项、不同动机，是规则引擎读不懂的人话（实测：Q6 选 B 但理由暴露 Si 动机，AI 判对了）
2. **写报告**：从"这个人的答案"里长出具体描述，而不是千人一面的模板

结论：**差异化 = AI 读理由 + 个性化报告**。理由框是主角，选项是快车道。理由没人填 → 差异化塌陷，所以理由填写率是命根子指标。

## 10. 产品解剖：每个模块的底层逻辑（介绍给别人版）

从外到内拆七层，每层一句话逻辑 + 一句大白话：

| 层 | 底层逻辑 | 大白话 |
|---|---|---|
| 浏览器 | 单页应用（SPA）：网站其实只有一个 HTML 文件，`/`、`/stats` 只是"门牌"，同一套代码按门牌演不同的戏 | 一家店，两个门，进哪扇门放哪出戏 |
| 前端 Vue | 状态机：页面永远是四种状态之一（答题中/分析中/报错/报告），点按钮就是换状态 | 导演切换舞台，剧本只有四幕 |
| 后端 Express | 掌柜守门：验格式 → 带 key 调 AI → 按合同验货（不合格退货重写，最多 3 次）→ 顺手记账 | 先查票、再办事、办完对货、最后记一笔 |
| prompt.md | AI 的劳动合同：角色、毕比分析框架、权重表、输出格式、六条红线、固定免责文案 | 雇专家的合同写得越细，活越漂亮 |
| DeepSeek | 差异化承重墙：读自由文本理由 + 写个性化报告（规则引擎读不懂人话，AI 读得懂） | 别人家是选择器，我们家是"读心者" |
| Blob 账本 | 只存聚合数字（次数/类型/填写率/赞踩），不存答案不存理由；仓库私密，只有带通行证的后端能碰 | 记流水账不记聊天记录，账本还锁在保险柜 |
| Vercel + DNS | serverless 函数"来客才醒"；域名 A/CNAME 两条记录把门牌指向服务器 | 服务员平时睡觉，客人按门牌敲门才醒 |

**为什么这套结构"AI 味"正**：AI 应用开发的骨架 = 前端收数据 → 后端带凭证调 AI → 结构化输出 + 验货 → 效果指标沉淀。这个项目把每一环都走了真货，不是教程玩具。

## 11. 部署篇：2026-08-17 实录（含四次排障）

**路线**：本地两个店（5173/3001）→ serverless 改造（菜谱 app.js / 叫醒入口 api/analyze.js / 店规 vercel.json / 总控台根 package.json）→ Vercel 绑定 GitHub（push 即自动部署）→ 腾讯云买域名 sherrymouse.top + 实名 → DNSPod 两条记录（@ → A 76.76.21.21；www → CNAME cname.vercel-dns.com）→ HTTPS 证书自动签发。

**四次排障（每次都从日志/证据找病因，不猜）**：

1. **国内打不开 vercel.app**：DNS 解析得出、TCP 连不上。三方证据（阿里 DNS、Vercel 主 IP 探测、手机流量对照）锁定：`*.vercel.app` 免费门牌被连坐封锁，Vercel 服务器本身没事 → 解法：买自己的域名当门牌
2. **FUNCTION_INVOCATION_FAILED**：函数醒来即崩。日志一句话破案：`Cannot find package 'express'`——Vercel 按需打包只看根目录行李清单，server/ 的依赖没上飞机 → 解法：build 命令补 `npm --prefix server install`
3. **/stats 404**：本地 Vite 有"找不到文件就回家"的 SPA 回退，线上静态托管没有 → 解法：vercel.json 加一条改道 `/stats → /index.html`
4. **反馈记录失败**：日志显示 `Cannot use public access on a private store`——新版 Blob 仓库默认私密，我的代码按老规矩公开写被拒 → 解法：写改 private、读改用 SDK 的 get()（自带通行证）

**两个安全升级顺带完成**：云端 key 走 Vercel 环境变量（本地 .env 不进 git）；Blob 新版用 OIDC——每次执行现场发一次性通行证，没有可泄露的长钥匙。

**部署第一定律**：构建绿勾 ≠ 运行正常。只有真实请求才能逼出真问题，日志是黑匣子，遇到就翻。
